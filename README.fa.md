# StackTunnel

[English](README.md) | **فارسی**

یک تانل معکوس کوچک TCP/UDP نوشته‌شده با Go، برای مسیرهایی که یک **فیلتر به‌ازای هر اتصال** دارند: فقط چند بسته‌ی اول هر اتصال جدید رد می‌شود، مگر اینکه اولین بسته شبیه SSH (یا STUN) باشد. یک باینری ایستا، یک کلید مشترک، و نصب‌کننده‌ی systemd.

> **وضعیت:** آزمایشی. روی یک سیستم (localhost) از اول تا آخر تست شده (TCP، UDP، انتقال حجمی، iperf3)، ولی **ممیزی نشده**، و رفتارش روی یک مسیر فیلترشده‌ی واقعی به نحوه‌ی کار آن فیلتر بستگی دارد. بخش‌های [نکات امنیتی](#نکات-امنیتی) و [محدودیت‌ها](#محدودیتها) را بخوان.

## نحوه‌ی کار

تانل **معکوس** است: سرور *بیرون* از شبکه‌ی فیلترشده (سرور «خارج») به سرور *داخل* (سرور «ایران») وصل می‌شود. کاربران به سرور داخل وصل می‌شوند و ترافیکشان از همین یک اتصال خروجی برمی‌گردد.

```
 کاربر ──► سرور ایران :443 ══════ تانل (شروع از سرور خارج) ══════ سرور خارج ──► 127.0.0.1:443
           (stacktunnel -mode server)                              (stacktunnel -mode client)
```

هر اتصال تانل با یک دست‌دهی ساختگی SSH شروع می‌شود تا بسته‌های اول شبیه یک نشست SSH باشند. بعد از آن همه‌چیز رمز و مالتی‌پلکس می‌شود.

## امکانات

- تانل معکوس: سرور خارج شروع‌کننده است، که مدل فیلتر هدف همین را لازم دارد
- فوروارد **TCP و UDP** (UDP داخل همان تانل TCP رمزشده حمل می‌شود)
- شروع شبیه SSH: یک خط `SSH-2.0-OpenSSH_9.6` به‌تنهایی، بعد `KEXINIT` و `KEX_ECDH_INIT/REPLY` و `NEWKEYS` با فرمت باینری واقعی SSH
- رمزنگاری ChaCha20-Poly1305 با **طول فریم رمزشده** و **padding** تصادفی
- چند اتصال موازی (`-conns`) روی [yamux](https://github.com/hashicorp/yamux)، اتصال مجدد خودکار با backoff، و keepalive
- بازه‌ی پورت (`8000-8100`) و **چندسروری**:
  - چند سرور خارج ← یک سرور ایران، هر کدام با پورت‌های متفاوت
  - یک سرور خارج ← چند سرور ایران
- نصب‌کننده‌ی تعاملی (`setup.sh`) که در صورت نیاز Go را نصب می‌کند، برنامه را می‌سازد، سرویس systemd می‌نویسد و پورت‌های `ufw` را باز می‌کند

## پیش‌نیازها

- لینوکس با systemd (برای نصب‌کننده؛ خود باینری هرجا Go اجرا شود کار می‌کند)
- Go نسخه‌ی ۱.۱۸ یا بالاتر برای ساخت (نصب‌کننده می‌تواند آن را نصب کند). وابستگی‌های ثابت‌شده: `yamux v0.1.1` و `golang.org/x/crypto v0.17.0`
- پورت تانل باید روی سرور ایران در دسترس باشد

## شروع سریع (پیشنهادی)

روی **هر دو** سرور، `main.go` و `setup.sh` را در یک پوشه بگذار و اجرا کن:

```bash
sudo bash setup.sh
```

۱. اول روی سرور **ایران** اجرا کن و گزینه‌ی `1) Iran server` را بزن. بگذار کلید تصادفی بسازد و آن را یادداشت کن.
۲. بعد روی سرور **خارج** اجرا کن، گزینه‌ی `2) Kharej server` را بزن و آی‌پی سرور ایران، همان کلید و همان پورت‌ها را بده.

نصب‌کننده `/usr/local/bin/stacktunnel`، `/etc/stacktunnel/config.env` و `stacktunnel.service` را می‌سازد (`Restart=always`، فعال در بوت).

```bash
sudo bash setup.sh status | logs | restart | show | uninstall
```

> اگر سروری نمی‌تواند Go یا ماژول‌های آن را دانلود کند، باینری را روی ماشینی که اینترنت سالم دارد بساز و کنار `setup.sh` بگذار. نصب‌کننده اگر باینری آماده‌ی `stacktunnel` را کنارش ببیند از همان استفاده می‌کند.

## ساخت و اجرای دستی

```bash
mkdir stacktunnel && cd stacktunnel          # main.go را اینجا بگذار
go mod init stacktunnel
go get github.com/hashicorp/yamux@v0.1.1 golang.org/x/crypto@v0.17.0
go mod tidy
go build -o stacktunnel .
```

**سرور ایران:**

```bash
./stacktunnel -mode server -key SECRET -tunnel :4000 -ports 443,8000-8100 -udp 51820
```

**سرور خارج:**

```bash
./stacktunnel -mode client -key SECRET -tunnel IRAN_IP:4000 -ports 443,8000-8100 -udp 51820 -conns 4
```

کاربران به `IRAN_IP:443` (TCP) یا `IRAN_IP:51820` (UDP) وصل می‌شوند و ترافیک به `127.0.0.1:443` / `127.0.0.1:51820` روی سرور خارج می‌رسد. سرویس واقعی تو باید همان‌جا گوش بدهد.

### پرچم‌ها

| پرچم | حالت | توضیح |
|---|---|---|
| `-mode` | هر دو | `server` (ایران) یا `client` (خارج) |
| `-key` | هر دو | کلید مشترک؛ باید همه‌جا یکسان باشد |
| `-tunnel` | هر دو | سرور: آدرس گوش دادن مثل `:4000`. کلاینت: `IP:port` یا لیست با کاما مثل `IP1:4000,IP2:4001` |
| `-ports` | هر دو | پورت‌ها یا بازه‌های TCP، مثل `443,2053,8000-8100` (هر بازه تا ۲۰۰۰ پورت) |
| `-udp` | هر دو | پورت‌ها یا بازه‌های UDP |
| `-pad` | هر دو | حداکثر بایت padding تصادفی هر فریم (پیش‌فرض `128`، مقدار `0` یعنی خاموش، حداکثر `4096`) |
| `-conns` | کلاینت | تعداد اتصال موازی تانل به هر سرور ایران (پیش‌فرض `4`) |
| `-bind` | سرور | آی‌پی که پورت‌های کاربران روی آن گوش می‌دهند (پیش‌فرض: همه‌ی رابط‌ها) |

### قواعد چندسروری

- `-ports` و `-udp` در **سرور** تعیین می‌کنند چه پورت‌هایی به کاربران نشان داده شود.
- `-ports` و `-udp` در **کلاینت** تعیین می‌کنند چه پورت‌هایی را سرویس می‌دهد و به هر سروری که وصل می‌شود اعلام می‌شود. اگر کلاینت به چند سرور ایران وصل است، اجتماع پورت‌ها را بده.
- اتصال کاربر فقط به کلاینتی می‌رسد که آن پورت را اعلام کرده باشد؛ اگر چند کلاینت اعلام کرده باشند، بار بینشان تقسیم می‌شود.
- شماره‌ی پورت در دو سمت یکی است (ایران `:443` ← خارج `127.0.0.1:443`). تغییر شماره‌ی پورت (remap) وجود ندارد.

## فرمت روی سیم

```
اتصال TCP (شروع از سرور خارج)
  → "SSH-2.0-OpenSSH_9.6\r\n"            به‌تنهایی، به‌عنوان اولین سگمنت داده
  ← "SSH-2.0-OpenSSH_9.6\r\n"
  → SSH_MSG_KEXINIT                       (لیست الگوریتم‌ها شبیه OpenSSH)
  ← SSH_MSG_KEXINIT
  → SSH_MSG_KEX_ECDH_INIT                 (۳۲ بایت: salt ۱۶ بایتی + پرکننده)
  ← SSH_MSG_KEX_ECDH_REPLY                (کلید میزبان ساختگی، ۳۲ بایت حاوی salt، امضای ساختگی)
  → SSH_MSG_NEWKEYS
  ← SSH_MSG_NEWKEYS
  بعد فریم‌ها:  [طول ماسک‌شده ۲ بایتی][ChaCha20-Poly1305( [طول واقعی ۲ بایتی][داده][padding] )]
  که یک نشست yamux را حمل می‌کنند
```

کلیدها برای هر جهت از `SHA-256(label ‖ PSK ‖ salt)` به‌دست می‌آیند. اولین stream در yamux یک پیام hello است که پورت‌های کلاینت را اعلام می‌کند؛ هر stream بعدی با یک هدر ۳ بایتی (پروتکل، پورت) شروع می‌شود. دیتاگرام‌های UDP داخل stream با پیشوند طول فرستاده می‌شوند. keepalive در yamux هر ۱۵ ثانیه است.

## نکات امنیتی

- کلید یک **کلید مشترک ثابت** است. **forward secrecy وجود ندارد** و دست‌دهی فقط یک ظاهرسازی است، نه تبادل کلید واقعی. اگر کلید لو برود، ترافیک ضبط‌شده قابل رمزگشایی است.
- طراحی رمزنگاری سفارشی است و **ممیزی مستقل نشده**. از کلید قوی و تصادفی استفاده کن (نصب‌کننده ۴۸ کاراکتر هگز می‌سازد). برای ترافیک حساس، یک پروتکل بررسی‌شده (WireGuard، مبتنی بر TLS، SSH و...) را *داخل* تانل اجرا کن.
- کلاینت فقط به `127.0.0.1` و پورت‌های لیست خودش وصل می‌شود و سرور فقط پورت‌های لیست خودش را باز می‌کند؛ پس کسی که کلید را دارد نمی‌تواند سرور را وادار به باز کردن پورت دلخواه یا کلاینت را وادار به رسیدن به هاست دلخواه کند.
- سرویس سمت خارج آی‌پی واقعی کاربران را نمی‌بیند (فقط `127.0.0.1` می‌بیند).
- کلید روی خط فرمان پروسه و در فایل سرویسی با دسترسی `600` (فقط root) نوشته می‌شود.

## محدودیت‌ها

- UDP روی TCP حمل می‌شود: با packet loss تأخیر ناگهانی (head-of-line blocking) رخ می‌دهد، پس برای بازی یا تماس صوتی مناسب نیست.
- فقط TCP و UDP؛ روی خود اتصال تانل نه TLS واقعی ممکن است نه QUIC (داخل تانل هر چیزی اشکال ندارد).
- فیلتری که بیشتر از بسته‌های ابتدایی را بررسی کند (مثلاً تحلیل بلندمدت ترافیک) ممکن است باز هم آن را تشخیص دهد. گزینه‌ی `-pad` و طول رمزشده این ریسک را کم می‌کنند، حذف نمی‌کنند.
- پورت پیش‌فرض تانل ۴۰۰۰ است (نه ۲۲) و آزادانه قابل تغییر است.
- احراز هویتی فراتر از کلید مشترک، حسابداری کاربر، یا رابط وب وجود ندارد.

## عیب‌یابی

لاگ‌ها علت را می‌گویند، پس اول `bash setup.sh logs` را ببین.

| پیام لاگ | معنی |
|---|---|
| `tunnel up from … : N tcp / M udp ports` (سرور) | یک کلاینت خارج وصل شد و پورت‌هایش را اعلام کرد |
| `connected to IP:port` (کلاینت) | دست‌دهی کامل شد |
| `disconnected: …` (کلاینت) | اتصال قطع یا رد شد (کلید اشتباه، آی‌پی یا پورت اشتباه، فایروال)؛ با backoff دوباره تلاش می‌کند |
| `connection … dropped, no kharej client has announced this port` (سرور) | کاربری وصل شد ولی هیچ کلاینتی آن پورت را سرویس نمی‌دهد: کلاینت قطع است یا `-ports` آن را ندارد |
| `cannot connect to local service 127.0.0.1:P` (کلاینت) | سرویس واقعی اجرا نیست یا روی `127.0.0.1:P` گوش نمی‌دهد |
| `request for tcp port P refused: not in this client's -ports` (کلاینت) | سرور پورتی را نشان می‌دهد که کلاینت برایش تنظیم نشده |

این‌ها را هم چک کن: پورت تانل در فایروال سرور ایران باز باشد، **کلید یکسان** روی همه‌ی سرورها، و **نسخه‌ی یکسان** باینری روی همه‌ی سرورها (دست‌دهی بین نسخه‌ها عوض شده است).

## تست سرعت

```bash
# سرور خارج
iperf3 -s -p 5201 -B 127.0.0.1
./stacktunnel -mode client -key KEY -tunnel IRAN_IP:4100 -ports 5201 -conns 4 -pad 0
# سرور ایران
./stacktunnel -mode server -key KEY -tunnel :4100 -ports 5201 -pad 0
iperf3 -c 127.0.0.1 -p 5201 -t 20 -P 8 -R
```

روی localhost باینری حدود ۱٫۱ تا ۱٫۲ گیگابیت بر ثانیه را تحمل کرد، پس CPU کمتر گلوگاه است؛ سرعت واقعی به مسیر بستگی دارد.

## مسائل حقوقی و سلب مسئولیت

این نرم‌افزار **همان‌طور که هست** و بدون هیچ ضمانتی ارائه می‌شود. رعایت قوانین کشور خودت و شبکه‌هایی که روی آن‌ها کار می‌کنی با خودت است؛ ابزارهای دورزدن فیلتر در بعضی کشورها محدودیت قانونی دارند. از آن برای دسترسی به سامانه‌هایی که اجازه‌ی استفاده از آن‌ها را نداری استفاده نکن.
