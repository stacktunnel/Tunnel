# StackTunnel

[English](README.md) | **فارسی**

یک تانل معکوس کوچک TCP/UDP برای شبکه‌های محدودشده. یک باینری ایستا، یک کلید مشترک، و نصب‌کننده‌ی تعاملی که آن را به‌صورت سرویس systemd راه‌اندازی می‌کند.

> **وضعیت:** روی سرورهای واقعی تست شده و کار می‌کند، اما ممکن است روی بعضی شبکه‌ها کار نکند. ممیزی مستقل نشده است. قبل از تکیه کردن، بخش‌های [نکات امنیتی](#نکات-امنیتی) و [محدودیت‌ها](#محدودیتها) را بخوان.

## معرفی

دو سرور درگیرند:

- **سرور ایران (داخل):** سروری که کاربرها به آن وصل می‌شوند.
- **سرور خارج (بیرون):** سروری که سرویس واقعی تو (پراکسی، VPN و...) روی آن اجرا می‌شود و *به* سرور ایران وصل می‌شود.

```
 کاربر ──► سرور ایران :443 ═══ تانل ═══ سرور خارج ──► 127.0.0.1:443 (سرویس تو)
```

می‌توانی چند سرور خارج را به یک سرور ایران وصل کنی (هر کدام با پورت‌های متفاوت)، یا یک سرور خارج را به چند سرور ایران.

## نصب

روی **هر دو** سرور:

```bash
curl -fsSL https://raw.githubusercontent.com/stacktunnel/Tunnel/main/setup.sh -o setup.sh
sudo bash setup.sh
```

نصب‌کننده باینری مناسب CPU را از آخرین [Release](https://github.com/stacktunnel/Tunnel/releases) دانلود می‌کند، با `SHA256SUMS` راستی‌آزمایی می‌کند و به‌صورت سرویس راه می‌اندازد.

۱. اول روی سرور **ایران** اجرا کن و گزینه‌ی `1) Iran server` را بزن. بگذار کلید تصادفی بسازد و کلید را یادداشت کن.
۲. بعد روی سرور **خارج** اجرا کن و گزینه‌ی `2) Kharej server` را بزن. آی‌پی سرور ایران، همان کلید و همان پورت‌ها را وارد کن.

این کار `/usr/local/bin/stacktunnel` را نصب می‌کند، تنظیمات را در `/etc/stacktunnel/config.env` ذخیره می‌کند، `stacktunnel.service` را می‌سازد (خودکار ری‌استارت می‌شود و در بوت فعال است) و می‌تواند پورت‌های لازم را در `ufw` باز کند.

```bash
sudo bash setup.sh status | logs | restart | update | show | uninstall
```

مطمئن شو سرویس واقعی روی سرور خارج روی `127.0.0.1` و روی همان پورت‌هایی که فوروارد می‌کنی گوش می‌دهد، و پورت تانل (پیش‌فرض `4000`) در فایروال سرور ایران باز است.

### به‌روزرسانی

```bash
sudo bash setup.sh update
```

نسخه‌ها با هم **سازگار نیستند**: سرور ایران و خارج را با هم به‌روز کن.

### اگر سروری به GitHub دسترسی ندارد

فایل مناسب CPU را روی ماشین دیگری از صفحه‌ی Releases بگیر، بعد آن را با نام `stacktunnel` کنار `setup.sh` روی سرور کپی کن:

| فایل | مناسب برای |
|---|---|
| `stacktunnel-linux-amd64` | بیشتر سرورها (x86-64) |
| `stacktunnel-linux-arm64` | سرورهای ARM ۶۴ بیتی |
| `stacktunnel-linux-armv7` | ARM ۳۲ بیتی (Raspberry Pi و مشابه) |
| `stacktunnel-android-arm64` | گوشی‌های اندروید (بخش [اندروید](#اندروید)) |
| `SHA256SUMS` | چک‌سام‌ها |

```bash
sha256sum -c SHA256SUMS --ignore-missing      # روی ماشینی که دانلود کردی
scp stacktunnel-linux-amd64 root@SERVER:~/stacktunnel
```

اگر فایلی با نام `stacktunnel` کنار `setup.sh` باشد، به‌جای دانلود از همان استفاده می‌شود.

## نسخه‌بندی

Releaseها از [Semantic Versioning](https://semver.org) پیروی می‌کنند (`v0.1.0`، `v0.1.1`، …). نسخه‌ی نصب‌شده را این‌طور ببین:

```bash
stacktunnel -version
```

تا وقتی نسخه‌ی major برابر `0` است، تغییر عدد **minor** (`0.1.x` ← `0.2.0`) ممکن است سازگاری بین سرورها را بشکند، پس سرور ایران و خارج را با هم به‌روز کن. نسخه‌های patch با هم سازگارند. [CHANGELOG.md](CHANGELOG.md) را ببین.

## سیستم‌عامل‌های دیگر

هر Release شامل باینری macOS (`darwin-amd64` و `darwin-arm64`)، Windows (`windows-amd64.exe` و `windows-arm64.exe`) و FreeBSD (`freebsd-amd64`) هم هست. `setup.sh` فقط **لینوکس با systemd** را پشتیبانی می‌کند؛ در سیستم‌های دیگر باینری پلتفرم خودت را دانلود کن و طبق بخش بعد دستی اجرا کن.

## اندروید

**آزمایشی.** باینری اندروید یک برنامه‌ی خط فرمان است، نه اپلیکیشن. ساده‌ترین راه اجرا، [Termux](https://termux.dev) است (از F-Droid یا از Releaseهای GitHub خودش نصب کن؛ نسخه‌ی Play Store قدیمی است).

```bash
# داخل Termux
pkg install curl
curl -fsSLO https://github.com/stacktunnel/Tunnel/releases/latest/download/stacktunnel-android-arm64
curl -fsSLO https://github.com/stacktunnel/Tunnel/releases/latest/download/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
mv stacktunnel-android-arm64 stacktunnel && chmod +x stacktunnel
./stacktunnel -version
```

مثل بخش [استفاده‌ی دستی](#استفادهی-دستی) اجرا کن، مثلاً به‌عنوان سمت خارج (کلاینت):

```bash
termux-wake-lock
./stacktunnel -mode client -key SECRET -tunnel IRAN_IP:4000 -ports 443 -conns 2
```

نکته‌ها:

- برای `-tunnel` از **آی‌پی** استفاده کن، نه نام دامنه.
- `setup.sh` روی اندروید کار نمی‌کند (systemd ندارد). بهینه‌سازی باتری را برای Termux خاموش کن و از `termux-wake-lock` استفاده کن تا اندروید پروسه را نکشد.
- فقط گوشی‌های ARM ۶۴ بیتی (`android-arm64`) باینری اختصاصی دارند. روی گوشی‌های ARM ۳۲ بیتی داخل Termux، `stacktunnel-linux-armv7` را امتحان کن.
- گوشی معمولاً پشت NAT است، پس معمولاً فقط به‌عنوان سمت **خارج (کلاینت)** به کار می‌آید، نه سروری که کاربرها به آن وصل می‌شوند.

## ساخت از سورس

به Go نسخه‌ی ۱.۱۸ یا بالاتر نیاز دارد.

```bash
git clone https://github.com/stacktunnel/Tunnel.git
cd Tunnel
go build -trimpath -ldflags="-s -w" -o stacktunnel .
```

Releaseها وقتی یک تگ مثل `v0.1.0` push شود، خودکار با GitHub Actions ساخته می‌شوند.

## استفاده‌ی دستی

**سرور ایران:**

```bash
./stacktunnel -mode server -key SECRET -tunnel :4000 -ports 443,8000-8100 -udp 51820
```

**سرور خارج:**

```bash
./stacktunnel -mode client -key SECRET -tunnel IRAN_IP:4000 -ports 443,8000-8100 -udp 51820 -conns 4
```

کاربرها به `IRAN_IP:443` (TCP) یا `IRAN_IP:51820` (UDP) وصل می‌شوند و به `127.0.0.1` روی همان پورت در سرور خارج می‌رسند.

### پرچم‌ها

| پرچم | حالت | توضیح |
|---|---|---|
| `-mode` | هر دو | `server` (ایران) یا `client` (خارج) |
| `-key` | هر دو | کلید مشترک؛ باید روی همه‌ی سرورها یکسان باشد |
| `-tunnel` | هر دو | سرور: آدرس گوش دادن مثل `:4000`. کلاینت: `IP:port` یا لیست با کاما مثل `IP1:4000,IP2:4001` |
| `-ports` | هر دو | پورت‌ها یا بازه‌های TCP، مثل `443,2053,8000-8100` (هر بازه تا ۲۰۰۰ پورت) |
| `-udp` | هر دو | پورت‌ها یا بازه‌های UDP |
| `-pad` | هر دو | حداکثر padding تصادفی هر فریم به بایت (پیش‌فرض `128`، مقدار `0` یعنی خاموش، حداکثر `4096`) |
| `-conns` | کلاینت | تعداد اتصال موازی تانل به هر سرور ایران (پیش‌فرض `4`) |
| `-rotate` | کلاینت | هر اتصال تانل را با این فاصله‌ی زمانی (با پراکندگی) عوض کن، مثل `5m` یا `3m` (پیش‌فرض `5m`، مقدار `0` خاموشش می‌کند) |
| `-bind` | سرور | آی‌پی که پورت‌های کاربران روی آن گوش می‌دهند (پیش‌فرض: همه‌ی رابط‌ها) |
| `-window` | هر دو | اندازه‌ی پنجره‌ی هر stream به KB (پیش‌فرض `1024`). روی مسیر کند یا ناپایدار `256` بگذار؛ مقدار بزرگ‌تر (تا `8192`) فقط برای مسیر سریع با تأخیر بالا |

### چند سرور

- `-ports` و `-udp` در **سرور** تعیین می‌کنند چه پورت‌هایی به کاربران ارائه شود.
- `-ports` و `-udp` در **کلاینت** تعیین می‌کنند چه پورت‌هایی را می‌تواند سرویس بدهد. اگر به چند سرور ایران وصل است، لیست ترکیبی پورت‌ها را بده.
- اتصال کاربر فقط به سرور خارجی فرستاده می‌شود که آن پورت را سرویس می‌دهد. اگر چند سرور این‌طور باشند، بار بینشان تقسیم می‌شود.
- شماره‌ی پورت در دو سمت یکی است؛ تغییر شماره‌ی پورت وجود ندارد.

## انتخاب اندازه‌ی پنجره (تست سرعت)

`-window` تعیین می‌کند هر اتصال چقدر داده می‌تواند همزمان در راه داشته باشد. پنجره‌ی **بزرگ‌تر** روی مسیر سریع با تأخیر بالا سرعت بیشتری می‌دهد، ولی روی مسیر کند یا شلوغ تأخیر زیر بار را بدتر می‌کند. بهترین مقدار به مسیر تو بستگی دارد، پس اندازه‌اش بگیر:

```bash
sudo bash setup.sh tune
```

اول روی سرور **ایران** اجرا کن (گزینه‌ی ۱، منتظر می‌ماند) و بعد روی سرور **خارج** (گزینه‌ی ۲). بعد از حدود یک دقیقه، سرور خارج جدولی مثل این و یک پیشنهاد چاپ می‌کند:

```
  -window   256 :     39.1 Mbit/s | idle RTT  201 ms | RTT under load: median   202 ms
  -window  1024 :     77.9 Mbit/s | idle RTT  201 ms | RTT under load: median   395 ms
  -window  4096 :     78.2 Mbit/s | idle RTT  201 ms | RTT under load: median   785 ms
  -window  8192 :     78.1 Mbit/s | idle RTT  201 ms | RTT under load: median  1386 ms

Recommended:  -window 1024
```

(نمونه از یک مسیر شبیه‌سازی‌شده است، نه شبکه‌ی واقعی.) پیشنهاد، کوچک‌ترین پنجره‌ای است که حداقل ۹۰٪ بهترین سرعت اندازه‌گیری‌شده را بگیرد. تست پیشنهاد می‌دهد مقدار را خودش اعمال کند؛ **همان مقدار را روی هر دو سرور** بگذار:

```bash
sudo bash setup.sh window 1024
```

تست از یک پورت جدا استفاده می‌کند (پیش‌فرض `4100`؛ در فایروال سرور ایران بازش کن) و تانل در حال کار را مختل نمی‌کند. جهت دانلود (از خارج به ایران) را با ۴ جریان موازی اندازه می‌گیرد.

## چرخش اتصال

روی بعضی مسیرها، یک اتصال تانل که مدت زیادی باز مانده، بعد از حدود ۱۰ تا ۲۰ دقیقه محدود می‌شود (پنجره‌ی ارسال فرومی‌ریزد و ارسال مجدد زیاد می‌شود) و با اتصال مجدد دوباره خوب کار می‌کند. برای جلوگیری از این، کلاینت هر چند وقت یک‌بار خودش یک اتصال جایگزین باز می‌کند و اتصال قدیمی را به‌آرامی کنار می‌گذارد: اتصال‌های جدید به اتصال تازه می‌روند، و اگر روی اتصال قدیمی انتقالی در حال انجام باشد، تا ۴۵ ثانیه فرصت دارد تمام شود، بعد بسته می‌شود.

```bash
./stacktunnel -mode client -key SECRET -tunnel IRAN_IP:4000 -ports 443 -rotate 5m
```

اگر باز هم بعد از تعداد دقیقه‌ی مشخصی قطعی دیدی، عدد را کمتر کن (مثلاً `-rotate 3m`). مقدار `-rotate 0` چرخش را کاملاً خاموش می‌کند. `setup.sh install` همین مقدار را روی سرور خارج می‌پرسد.

## عیب‌یابی

اول `sudo bash setup.sh logs` را ببین.

| پیام لاگ | معنی |
|---|---|
| `tunnel up from … : N tcp / M udp ports` (ایران) | یک سرور خارج وصل شد |
| `connected to IP:port` (خارج) | اتصال برقرار شد |
| `disconnected: …` (خارج) | اتصال قطع یا رد شد: کلید، آی‌پی و پورت، و فایروال را چک کن. خودکار دوباره تلاش می‌کند |
| `… dropped, no kharej client has announced this port` (ایران) | کاربری وصل شد ولی هیچ سرور خارجی آن پورت را سرویس نمی‌دهد: خاموش است یا `-ports` آن را ندارد |
| `cannot connect to local service 127.0.0.1:P` (خارج) | سرویس واقعی اجرا نیست یا روی `127.0.0.1:P` گوش نمی‌دهد |
| `request for tcp port P refused: not in this client's -ports` (خارج) | سرور ایران پورتی را ارائه می‌دهد که این سرور خارج برایش تنظیم نشده |

این‌ها را هم چک کن: پورت تانل در سرور ایران باز باشد، **کلید یکسان** روی همه‌جا، و **نسخه‌ی یکسان** (نسخه‌ها با هم سازگار نیستند) روی همه‌ی سرورها.

## تست سرعت

یک روش ساده برای اندازه‌گیری سرعت از داخل تانل، با یک فایل آزمایشی روی سرور خارج:

```bash
# سرور خارج: ساخت فایل ۲۰۰ مگابایتی و سرو آن روی localhost
head -c 200000000 /dev/urandom > big.bin
python3 -m http.server 8080 --bind 127.0.0.1 &
./stacktunnel -mode client -key KEY -tunnel IRAN_IP:4100 -ports 8080 -conns 4
# سرور ایران
./stacktunnel -mode server -key KEY -tunnel :4100 -ports 8080
curl -o /dev/null -w "%{speed_download} bytes/s\n" http://127.0.0.1:8080/big.bin
```

برای کار عادی از سرویس `setup.sh` استفاده کن؛ این فقط یک تست موقت است (بعدش هر دو پروسه‌ی تست را ببند). سرعت واقعی به مسیر بین سرورها بستگی دارد؛ `-conns` بین ۴ تا ۸ و چند دانلود موازی را امتحان کن.

## نکات امنیتی

- ترافیک با یک **کلید مشترک ثابت** رمز می‌شود. **forward secrecy وجود ندارد:** اگر کلید لو برود، ترافیک ضبط‌شده قابل رمزگشایی است.
- طراحی رمزنگاری سفارشی است و **ممیزی مستقل نشده**. از کلید طولانی و تصادفی استفاده کن (نصب‌کننده یکی می‌سازد). برای ترافیک حساس، یک پروتکل کاملاً بررسی‌شده را داخل تانل اجرا کن.
- سرور خارج فقط به `127.0.0.1` روی پورت‌های لیست خودش وصل می‌شود و سرور ایران فقط پورت‌های لیست خودش را باز می‌کند.
- سرویس واقعی تو همه‌ی اتصال‌ها را از `127.0.0.1` می‌بیند، نه آی‌پی واقعی کاربران.
- کلید در فایلی با دسترسی `600` (فقط root) ذخیره می‌شود و روی خط فرمان پروسه دیده می‌شود.

## محدودیت‌ها

- UDP روی همان اتصال TCP حمل می‌شود، پس با packet loss ممکن است تأخیر ناگهانی ببینی. برای بازی یا تماس صوتی مناسب نیست.
- حسابداری کاربر، رابط وب، یا احراز هویتی فراتر از کلید مشترک وجود ندارد.
- تضمینی نیست که روی هر شبکه‌ای کار کند یا با تغییر شبکه به کار ادامه بدهد.

## سلب مسئولیت

**همان‌طور که هست** و بدون هیچ ضمانتی ارائه می‌شود. رعایت قوانین کشور خودت با خودت است؛ ابزارهای این‌چنینی در بعضی کشورها محدودیت قانونی دارند. از آن برای دسترسی به سامانه‌هایی که اجازه‌ی استفاده از آن‌ها را نداری استفاده نکن.
